## 一、遗留订单 #12 amount missing 只读巡检报告

### 背景

后端日志 WARN 级别输出：遗留订单 #12 `amount` 为 null。该字段在 Prisma schema 中定义为 `Int?`（可选），历史数据缺少金额。

### 只读检查（不修改）

1. 确认 `Order.amount` 字段在 schema 中为 `Int?`（非 `@default`）
2. 统计数据库中 `amount IS NULL` 的订单数量
3. 确认受影响订单的 `taskId`、`workerId`、`status`，判断是否属于早期测试数据
4. 检查 Wallet / LedgerEntry 表是否存在对应记录
5. 输出只读巡检报告，**不插入数据，不补全金额**

### 产出

`docs/openclaw-reports/v0.2.4-order-12-amount-audit.md`

只读查询（通过 Prisma Studio 或 pm2 日志抓取），不修改代码。

## 三、后端全局异常过滤器 / 响应格式统一

### 现状

```
apps/backend/src/common/
├── filters/
│   └── http-exception.filter.ts     ← 已实现
└── interceptors/
    └── transform.interceptor.ts     ← 已实现
```

**问题**：两者均已实现但**未全局注册**。当前异常返回 NestJS 默认格式，成功响应无统一包装。

### 规划

1. 在 `main.ts` 中注册 `app.useGlobalFilters(new HttpExceptionFilter())`
2. 在 `main.ts` 中注册 `app.useGlobalInterceptors(new TransformInterceptor())`
3. 统一成功响应格式：
   ```json
   { "code": 0, "message": "OK", "data": <实际数据> }
   ```
4. 统一异常响应格式（已有）：
   ```json
   { "statusCode": 400, "error": "BadRequest", "message": "...", "path": "/api/...", "timestamp": "..." }
   ```
5. 可选：添加 `ApiResponse<T>` 全局类型定义

### 风险

- 纯注册行为，不修改 filter/interceptor 内部逻辑
- 需确认 transform interceptor 不会破坏已有分页格式（已处理 `code in data` 跳过逻辑）
- 上线后需验证 `/api/` 裸路由返回格式

## 五、日志规范化

### 现状

- 后端使用 `console.log` / `console.error` 原始输出
- PM2 输出到 stdout/stderr，journal 日志无结构化格式
- 异常过滤器已输出结构化 JSON 日志（`console.error('[HttpExceptionFilter]', {...})`）

### 规划

1. 评估是否需要引入 NestJS 内置 Logger 或结构化日志库（winston/pino）
2. 如果引入，影响范围评估：
   - `main.ts` 的 `app.useLogger(app.get(Logger))`
   - 替换所有 `console.log` 为 `this.logger.log()`
3. 日志级别定义：
   - DEBUG：开发环境调试
   - LOG：正常业务操作（创建用户、登录等）
   - WARN：非预期但可恢复（如 #12 amount missing）
   - ERROR：不可恢复错误
4. 可选但不必须：日志上下文（`userId`、`requestId`、`path`）
5. 结构化日志输出样例：
   ```json
   { "level": "warn", "timestamp": "...", "context": "OrderService", "message": "Order #12 amount is null", "orderId": 12 }
   ```

### 风险

- 引入日志库可能带来依赖变更
- 直接替换 `console.log` 可能影响线上调试
- 建议先使用 NestJS 内置 Logger，待 v0.2.5 再评估是否需要 winston

## 六、Swagger / OpenAPI 文档

### 现状

```
main.ts 中已配置：
- DocumentBuilder (title, version, bearerAuth)
- SwaggerModule.createDocument
- SwaggerModule.setup('api/docs')
```

**问题**：
- Controller 和 DTO 上缺少 `@ApiTags`、`@ApiOperation`、`@ApiBearerAuth`、`@ApiProperty` 装饰器
- Swagger UI 可以访问，但接口描述基本为空
- 用户认证后的 JWT token 输入方式未优化

### 规划

1. 目标：让 `/api/docs` 可用且可读，**不要求完整覆盖每一个字段**
2. 优先添加装饰器的模块：
   - `AuthModule`（登录/注册 — 最常用）
   - `UserModule`（个人中心 — 高频调用）
   - `AdminModule`（治理接口 — 需要文档）
3. 必须添加的装饰器类型：
   - `@ApiTags('Auth')` 分组
   - `@ApiOperation({ summary: '用户登录' })` 简要说明
   - `@ApiBearerAuth()` 需要 token 的接口
   - `@ApiProperty({ example: 'user@example.com' })` 关键 DTO 字段
4. 不修改：
   - 不修改 Swagger UI 配置项
   - 不修改 Swagger 路径（保持 `/api/docs`）
