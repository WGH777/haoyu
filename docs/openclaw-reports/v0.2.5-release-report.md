## 4. 后端登录限流说明

### LoginThrottleGuard

基于内存的 NestJS Guard，不持久化，不依赖数据库。

| 维度 | 窗口 | 上限 | 清除条件 |
|------|:----:|:----:|---------|
| **IP 请求数** | 15 分钟 | 10 次 | 成功登录后 `clearIp()` |
| **Email 失败数** | 15 分钟 | 5 次 | 成功登录后 `clearEmailFails()` |
| **过期清理** | 60 秒周期 | — | 自动删除过期记录 |
| **进程重启** | — | — | 内存清零，自动解封 |

### 请求流

```
POST /api/auth/login
  ├─ LoginThrottleGuard.canActivate()
  │   ├─ IP 检查（≥10 次）→ 429 JSON
  │   └─ Email 检查（≥5 次失败）→ 429 JSON
  ├─ AuthService.signIn()
  │   ├─ 成功 → clearEmailFails + clearIp
  │   └─ 失败 → recordEmailFail
  └─ 返回 200 / 401 / 429
```

## 5. Nginx 登录限流说明

### limit_req 配置

```nginx
map $http_cf_connecting_ip $login_limit_key {
    ""      $binary_remote_addr;      # 非 CF 场景回退
    default $http_cf_connecting_ip;   # CF 真实 IP
}
limit_req_zone $login_limit_key zone=login_limit:10m rate=30r/m;

location /api/auth/login {
    limit_req zone=login_limit burst=5 nodelay;
    limit_req_status 429;
    error_page 429 @login_429;        # JSON 响应
    proxy_set_header X-Real-IP $login_limit_key;  # 真实 IP 透传
}
```

### 双层 429 响应（均为 JSON）

| 层 | Content-Type | Body |
|---|:-----------:|------|
| **Nginx** limit_req | `application/json` | `{"statusCode":429,"error":"TooManyRequests","message":"Too many login attempts, please try again later","path":"/api/auth/login","timestamp":"..."}` |
| **后端** LoginThrottleGuard | `application/json; charset=utf-8` | `{"statusCode":429,"error":"HttpException","message":"登录请求过于频繁，请稍后再试","path":"/api/auth/login","timestamp":"..."}` |
