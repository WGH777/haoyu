## 限流策略

| 维度 | 窗口 | 上限 | 触发行为 |
|------|:----:|:----:|---------|
| **IP 请求数** | 15 分钟 | 10 次登录请求 | 超限 → 429 |
| **Email 失败数** | 15 分钟 | 5 次失败 | 超限 → 429 |
| 过期清理 | 每 60 秒 | 扫描并删除过期记录 | `setInterval.unref()` |
| 进程重启 | — | 内存清零，自动解封 | 无持久化 |

## 成功登录清理机制

```
POST /api/auth/login
  ├─ LoginThrottleGuard.canActivate()
  │   ├─ IP 检查：当前窗口请求数 > 10? → 429
  │   └─ Email 检查：当前窗口失败数 ≥ 5? → 429
  │   └─ 通过 → 递增 IP 计数，返回 true
  ├─ AuthService.signIn()
  │   ├─ ✅ 成功 → 清除该 email 失败记录（clearEmailFails）
  │   └─ ❌ 失败 → 记录该 email 失败（recordEmailFail）
  └─ 返回 200 / 401 / 429
```

## 429 响应示例

```json
{
  "statusCode": 429,
  "error": "HttpException",
  "message": "登录请求过于频繁，请稍后再试",
  "path": "/api/auth/login",
  "timestamp": "2026-06-05T11:30:11.301Z"
}
```

- 格式与 `HttpExceptionFilter` 兼容（`statusCode`, `error`, `message`, `path`, `timestamp`）
- **不泄漏账号是否存在**（无论 IP 限流或 email 限流，返回相同消息）
