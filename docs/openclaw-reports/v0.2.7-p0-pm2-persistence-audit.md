## 1. 根因

**PM2 daemon 进程被 OpenClaw 工具进程的清理机制杀死后，pm2-root.service 没有运行。**

关键发现链：

| 检查项 | 结果 |
|--------|:----:|
| `pm2-root.service` 配置 | `enabled` ✅（开机自动恢复）|
| Restart 策略 | `on-failure` ✅ |
| `ExecStart` | `pm2 resurrect` ✅（开机恢复保存进程）|
| **但 `systemctl status pm2-root`** | **`inactive (dead)`** ❌ |
| PM2 daemon 状态 | 之前由 OpenClaw 工具进程启动，工具进程退出后 daemon 被杀死 |
| systemd 未自动重启 PM2 | PM2 daemon 以单独进程运行，不在 systemd `cgroup` 下，systemd 无法守护它 |

**根因一句话**: PM2 以独立进程运行而非 systemd daemon 实例时，进程被清理工具杀掉后不会自动拉起，因为 systemd 控制的 `pm2-root.service` 当时是 `inactive`。

## 4. 修复动作

只执行了以下操作（未修改代码/数据库/Nginx）：

```bash
systemctl start pm2-root.service
```

效果：

- `pm2-root.service` 从 `inactive (dead)` 变为 **`active (running)`**
- PM2 daemon 现在运行在 systemd `cgroup` 下（PID `3984541 "PM2 v7.0.1: God Daemon"`）
- 如果被杀掉，systemd `Restart=on-failure` 会重新拉起
- 后续 `pm2 resurrect` 将在开机时恢复 haoyu-backend
