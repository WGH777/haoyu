## 一、产品愿景

浩煜不只是线上协作平台。

最终形态是 **线上平台 + 移动端入口 + 线下服务网点 + 实时任务大屏** 组成的一体化协作系统。

> 让复杂协作流程变得像任务化服务一样清晰、高效、可追踪。

用户可以在手机上发布需求，在电脑上管理订单，在实体店获得店员协助，在大屏上看到实时协作动态——所有数据实时同步，所有操作可追溯。

## 二、三端定义

### 2.1 手机端（普通用户主入口）

**用户群：** 需求发布者、服务提供者

**核心功能：**
- 发布需求（支持语音、拍照、分步引导）
- 浏览任务大厅，筛选附近/线上
- 接单、开始服务、提交成果
- 验收确认、评价
- 钱包管理、充值提现
- 通知中心
- 争议发起与进度查看

**体验要求：**
- 适配 375-428px 移动视口
- 触控友好（最小点击区域 44px）
- 表单简化（减少输入，增加选择）
- 发送需求支持语音转文字
- 拍照直接上传为需求配图

### 2.2 电脑端（管理/运营入口）

**用户群：** 管理员、店员、仲裁员、财务审核员

**核心功能：**
- 管理后台（订单/用户/争议/资金）
- 代办工作台（店员协助用户发布）
- 仲裁处理中心
- 财务审核与对账
- 数据分析看板
- 公告与规则管理

### 2.3 大屏/店面端（展示入口）

**用户群：** 店内顾客、路人

**核心功能：**
- 实时任务面板（滚动展示新需求）
- 服务者排行榜（完成榜/信用榜）
- 平台动态（今日数据、累计协作）
- 热门需求分类
- 平台公告与活动
- 本地服务热点地图

### 2.4 后续可扩展

| 形态 | 优先级 | 说明 |
|------|:---:|------|
| PWA | P1 | 手机桌面入口 + 轻量离线 |
| 微信小程序 | P2 | 降低注册门槛 |
| iOS/Android App | P3 | 原生体验 |
| Kiosk 终端 | P2 | 店内自助服务机 |

## 三、实体店模式

### 3.1 定位

浩煜实体服务网点，主要服务两类人群：
- **不会/不愿使用智能手机的长者或技术弱势群体**
- **需要面对面确认的高价值协作**

### 3.2 店员工作台

店员通过电脑端代办工作台协助用户：

| 操作 | 描述 |
|------|------|
| 采集需求 | 店员与用户沟通，录入需求标题、描述、预算 |
| AI 辅助整理 | 系统自动优化文案，补充分类和风险等级建议 |
| 用户确认 | 展示整理后的需求，用户确认预算+规则 |
| 生成回执 | 打印或发送二维码回执，用户可扫码追踪 |
| 后续跟进 | 用户可通过手机/短信/到店继续操作 |

### 3.3 店面展示

- **实时任务大屏：** 展示本地需求、热门服务、完成动态
- **排行榜：** 本月完成榜、信用榜、新人榜
- **公告板：** 平台规则、活动通知、安全提醒
- **二维码入口：** 扫码直接进入手机端

## 四、线下服务流程

```
用户进店咨询
    ↓
店员采集需求（代办工作台）
    ↓
AI 辅助整理为正式需求
    ↓
用户确认预算、验收标准、规则
    ↓
系统发布需求，生成回执（打印 / 二维码 / 短信）
    ↓
服务者接单（线上或店内推荐）
    ↓
用户可随时通过手机/到店查看进度
    ↓
服务完成 → 用户确认（手机 / 到店 / 短信验证）
    ↓
资金结算，信用沉淀
```

### 回执机制

- 每次线下操作生成回执
- 回执包含：需求编号、内容摘要、金额、时间、二维码
- 用户扫码可查看实时状态
- 确认操作支持：手机确认、短信验证码、店员见证签名

## 五、游戏化设计（不儿戏）

### 5.1 核心理念

借鉴任务大厅、进度反馈、排行榜、成就记录等机制，对外表达为：
- 「任务化服务流程」
- 「沉浸式协作体验」
- 「可视化办理路径」

### 5.2 具体机制

| 机制 | 表达 | 说明 |
|------|------|------|
| 进度反馈 | 任务状态时间线 | 接单→开始→提交→验收，每步可见 |
| 排行榜 | 完成榜/信用榜/新人榜 | 大屏和手机端展示 |
| 成就记录 | 里程碑徽章 | 首单完成、10单达人、好评率>95% |
| 实时动态 | 任务大厅滚动 | 新需求、新完成、新评价 |
| 协作节点 | 子任务进度条 | 复杂任务拆解可视化 |

### 5.3 红线

| 🚫 禁止 | 说明 |
|------|------|
| 低俗梗 | 不用网络过时热梗做文案 |
| 过度游戏化 | 不放虚拟金币、抽奖、战力值 |
| 资金玩笑 | 结算/退款/仲裁场景保持严肃 |
| 攻击性文案 | 不贬低用户、不给负面标签 |

## 六、权限与风控

### 6.1 角色定义

| 角色 | 权限 | 限制 |
|------|------|------|
| **普通用户** | 发布、接单、支付、确认、评价 | 不能操作系统设置 |
| **店员** | 代发需求、查看任务、协助确认 | 不能动资金、不能裁决 |
| **店长** | 店员权限 + 管理店员、查看店面数据 | 不能动资金 |
| **管理员** | 订单管理、用户管理、公告发布 | 不能裁决争议 |
| **仲裁员** | 争议受理、证据收集、裁决 | 不能修改订单 |
| **财务审核员** | 查看账本、审批提现、对账 | 不能裁决争议 |
| **超级管理员** | 全部权限 | Founder 亲自担任 |

### 6.2 线下代办规则

- 店员只能协助，不得私自操作用户资金
- 确认结算、修改敏感信息必须用户本人确认
- 所有线下代办操作写入 AuditLog
- 涉及资金、验收、仲裁必须由用户本人确认（签名/短信/扫码）
- 支持二维码回执确认机制

### 6.3 审计要求

- 所有线下操作记录：操作人、操作时间、操作内容、用户确认方式
- 店面摄像头/时间戳作为辅助证据（可选）
- 店员操作日志定期审查

## 七、技术路线

### 阶段一：响应式 Web（当前→近期）

- 适配手机（375px+）、桌面（1024px+）、大屏（1920px+）
- 使用 CSS 媒体查询 + 弹性布局
- 路由预留：`/mobile`、`/store`、`/display`

### 阶段二：PWA（近期）

- Service Worker 离线缓存
- 添加到手机桌面
- 推送通知
- 轻量离线浏览

### 阶段三：小程序 / App（中期）

- 微信小程序降低注册门槛
- 原生 App 提供更流畅体验
- 与 Web 端数据互通

### 阶段四：实体终端（中期）

- Kiosk 模式（店内自助服务机）
- 大屏展示模式（实时数据看板）
- 打印机集成（回执打印）

### 路由规划

| 路由 | 用途 |
|------|------|
| `/mobile` | 手机端适配主页 |
| `/store` | 店员代办工作台 |
| `/display` | 大屏展示页 |
| `/kiosk` | 自助服务终端 |
| `/admin` | 管理后台（已有） |
